# ROMY × Apohara 2.0 — reconciliation note (2026-06-11)

## Summary (1 paragraph)

ROMY reconciles with the three Apohara 2.0 compression layers
(`turbovec-rag`, `llmlingua2-extend`, `turboquant-kv-upstream`) as
the **isolation contract** that backs INV-15 on the serving side —
not as a memory-optimizer that competes with vLLM's native Automatic
Prefix Caching. The reconciliation is mostly **docs + tests + a
micro-bench**; the plugin's public surface (`ROMYConfig`,
`vLLMRomyPlugin`, `PreAttentionHook`, `PostAttentionHook`, the
`vllm.general_plugins` entry-point) is **unchanged**. The
`PrefixSaltPlanner` already encodes the isolation contract
(`shared_salt` for the 84.7 % APC hit path, `isolated_salt` for the
INV-15 dense path), so no production code change is required for the
reframe.

## The AUDIT #19 baseline (regression anchors)

The F1-F3 baseline is documented at
[`AUDIT.md` §19](../../AUDIT.md#19-atom-f1-f3-validated-on-hardware--the-honest-scope-full-attention-2026-05-29)
(2026-05-29, 1× MI300X, Qwen3-32B, full-attention):

- **Shared `cache_salt`** (non-judge requests on the same anchor +
  CLA group) → vLLM APC prefix-cache hit rate **84.7 %**.
- **Isolated `cache_salt`** (judge-class requests, `use_dense=True`,
  INV-15 dense path) → vLLM APC prefix-cache hit rate **0.0 %**
  between judges. Physical isolation via the block-hash keying.
- TTFT: shared **0.058 s** vs isolated **0.135 s** distinct (−57 %).

These two numbers are the **regression anchors** for the
post-ABANDON reconciliation: any future change to ROMY /
`PrefixSaltPlanner` / `cache_salt` plumbing must preserve
`judge_hit_rate = 0.0` (the isolated path) and
`shared_hit_rate_estimate ≥ 0.847` (the shared path, on the same
hardware class).

## The post-ABANDON reframe

GATE #0 (2026-06-11, 1× MI300X, real vLLM) was a **preregistered
test of ROMY as a memory-optimizer** — manual `cache_salt` plane
layered on top of vLLM APC, on a shared-prefix workload. **Verdict:
ABANDON** — ROMY was −22 % in aggregate throughput vs APC alone, and
+147 % in TTFT. vLLM APC already captures 97.2 % of the shared
prefix hits for free; the manual `cache_salt` plane adds accounting
overhead without giving the optimizer anything it doesn't already
have.

ROMY survives because **APC alone is on the shared path only** —
judges still need a deliberate unique salt to be physically
isolated, and that is what `PrefixSaltPlanner.isolated_salt`
delivers. The "isolation contract" framing is the durable one. The
"memory-optimizer" framing is dead and is no longer used in this
repo's docs (this note, `LMCACHE.md` post-ABANDON section,
`README.md` post-ABANDON section, AUDIT #21).

## What lands in this US-007 commit

Three artifacts, plus this note. No production code change.

1. **Regression test** —
   `tests/test_romy_plugin.py::test_romy_judge_isolation_zero_hit_rate_regression_on_audit_19`
   — for 100 judge-class requests (`use_dense=True`) and 100
   non-judge requests (`use_dense=False`), assert every judge gets a
   unique `cache_salt` (no two judges share a salt) and at least 2
   non-judges share the deterministic shared salt. Cross-references
   AUDIT #19 in the test docstring.
2. **Planner-level regression** —
   `tests/test_prefix_salt_planner.py::test_prefix_salt_planner_judge_isolation_unique`
   — calls `PrefixSaltPlanner.isolated_salt(...)` for 100 distinct
   `request_id` values and asserts all 100 salts are unique; calls
   `shared_salt(...)` 10 times with the same inputs and asserts
   all 10 are identical. The shared-path determinism is the
   precondition for the 84.7 % APC hit rate.
3. **Micro-bench (coexistence, not overlap)** —
   `tests/benchmarks/romy_vs_turboquant_kv.py` — runs the
   `PrefixSaltPlanner` (ROMY salt axis) and the CPU-scalar
   `TurboQuantKVShim` (US-006 storage axis) on the same synthetic
   input shape, asserts `judge_hit_rate = 0.0`,
   `shared_hit_rate_estimate = 0.847`, `coexistence_pass = True`,
   emits a JSON summary with `hardware = "cpu"`. The bench is
   importable from pytest; it does **not** require a subprocess
   for the local CPU path.

## Honest scope (the bench does NOT measure)

- **VRAM reduction** is not measured — the bench uses the CPU
  scalar path of `TurboQuantKVShim`. The 2.5× compression
  threshold is asserted in `bench_kv.py` and audited in
  AUDIT #25; the micro-bench here only asserts that ROMY and the
  TurboQuant-KV shim can run on the same input shape without
  raising.
- **Throughput, TTFT, APC hit rate on real silicon** are not
  measured. Those are `bench_kv.py`'s job on the H100 / MI300X
  pivot (with the `PIVOT_BANNER`); the local slim venv has no
  vLLM, so they are out of scope.
- **The pre/post attention hooks are not invoked at runtime** —
  AUDIT #18 + AUDIT #20: the `register()` entry-point is real,
  but the hooks are unit-tested utilities, NOT wired to the vLLM
  runtime. The micro-bench does not invoke them as if they were
  a runtime path.
